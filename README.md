# ResearchGap

A multimodal, multi-agent research assistant powered by **Gemma 4**. Upload up to three papers; ResearchGap
reads their text **and their figures and tables**, compares the evidence, proposes research gaps, and verifies
every gap against the exact page it came from.

> Gaps are relative to the uploaded papers. ResearchGap says "not studied in the uploaded papers", never
> "nobody has studied this".

## How it works

```
PDFs ──PyMuPDF──► page text with [Page N] markers
     └─────────► figure/table pages rendered as images
                        │
  Agent 1  Paper Analyst      text + page images → methods, metrics (with definitions), findings,
                              limitations, numbers read from charts, figure-vs-text contradictions
  Agent 2  Comparator         cross-paper matrix, agreements, contradictions, metric-definition conflicts,
                              dimensions no paper studies
  Agent 3  Gap Finder         research questions, each with page/figure evidence + suggested experiment
  Agent 4  Verifier           (a) deterministic check: does the paper/page exist, is the quote on that page,
                                  is the figure caption there?
                              (b) Gemma re-reads the cited pages and images and judges the gap
                              A gap with no locatable evidence is always rejected.
```

All four agents use one hosted Gemma 4 model (`gemma-4-31b-it` by default) with different prompts. Outputs are
validated with Pydantic (`researchgap/schemas.py`); invalid JSON is sent back to the model with the validation
error for repair.

**Text-only vs multimodal.** The Paper Analyst also runs once per paper without images. The dashboard shows
what a text-only reader concludes next to what Gemma finds in the figures, and flags figures that contradict
the paper's own text.

### Dashboard

- **Research gaps** with evidence-to-gap traceability: each citation shows its check status and can open the
  source page with the quote highlighted.
- **Comparison matrix**, agreements, contradictions, metric-definition warnings.
- **Experimental results** chart of numbers extracted from text, tables and charts.
- **Text-only vs multimodal** comparison.
- **Export** as Markdown report or JSON.

## Run locally

Requires Python 3.10+.

```bash
git clone https://github.com/Purtee13/ResearchGap-.git
cd ResearchGap-
python -m venv .venv
.venv\Scripts\activate          # Windows  (macOS/Linux: source .venv/bin/activate)
pip install -r requirements.txt
copy .env.example .env          # macOS/Linux: cp .env.example .env
```

Put your key from <https://aistudio.google.com/apikey> in `.env` as `GEMINI_API_KEY=...`, then:

```bash
streamlit run app.py
```

Open http://localhost:8501. You can also paste a key in the sidebar instead of using `.env`.

### Try it without a key

Choose **Offline demo** in the sidebar, click **Use sample papers**, then **Show offline demo**. This shows
precomputed output for three bundled synthetic papers (generated by `researchgap/sample_papers.py`). Each one
makes a broad written claim that its own chart contradicts, which is the case a text-only assistant misses.
Switch to **Live** mode with a key to run the real agents on the same papers or your own PDFs.

### Tests

```bash
pip install pytest
pytest -q
```

## Deploy on Cloudflare

See [deploy/cloudflare/README.md](deploy/cloudflare/README.md). Short version, with the app running locally:

```bash
cloudflared tunnel --url http://localhost:8501
```

For a permanent URL use `docker compose up -d --build` with a named Cloudflare Tunnel token, or deploy the
container to Cloudflare Containers with `wrangler deploy`.

## Configuration

| Variable | Default | |
|---|---|---|
| `GEMINI_API_KEY` | | Required for Live mode |
| `GEMMA_MODEL` | `gemma-4-31b-it` | or `gemma-4-26b-a4b-it` |
| `MAX_IMAGES_PER_PAPER` | 6 | Figure/table pages sent to Gemma per paper |
| `RENDER_DPI` | 110 | Page image resolution |
| `CLOUDFLARE_TUNNEL_TOKEN` | | Only for `docker compose` |
